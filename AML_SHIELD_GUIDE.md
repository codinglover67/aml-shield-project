# AML Shield — Project Guide & Run Notes

## What This Project Is

AML Shield is a compliance tool that does three things:
1. **Transaction Monitoring** — ML models (Random Forest, Decision Tree, Logistic Regression) trained on a CSV dataset to flag suspicious transactions
2. **Sanctions Screening** — Scrapes MAS sanctions lists and fuzzy-matches names against them
3. **KYC Screening** — PEP checks via OpenSanctions + adverse media search via DuckDuckGo/Google/GDELT

## First-Time Setup

### 1. Create and activate a virtual environment

```bash
cd "<your directory>"
python3 -m venv venv
source venv/bin/activate
```

Every time you open a new terminal, run `source venv/bin/activate` before anything else.

### 2. Install dependencies

```bash
pip install fastapi uvicorn numpy pandas scikit-learn httpx beautifulsoup4 lxml tldextract python-multipart
```

### 3. Place your CSV

Make sure `SAML-D.csv` is in the same folder as `main_V5.py`. The ML models train on this file.

## Running the Server

```bash
source venv/bin/activate
python3 main_V5.py
```

Then open: **http://localhost:8000**

### What happens on startup (automatically):
1. Checks if `models.pkl` exists — if not, trains ML models on `SAML-D.csv` (takes a few minutes first time)
2. Checks if `mas_sanctions.db` exists — if not, scrapes MAS sanctions website and builds the DB
3. Starts a background thread that re-scrapes sanctions every 24 hours
4. Starts loading transaction CSV into memory in chunks (progress shown in UI)

### Optional flags:

```bash
# Force retrain models even if models.pkl exists
python3 main_V5.py --retrain

# Use a different CSV
python3 main_V5.py --csv your_file.csv

# Use a different port
python3 main_V5.py --port 8080

# Use a different sanctions DB path
python3 main_V5.py --db path/to/sanctions.db
```

### Optional env vars (for better adverse media coverage):

```bash
# Google Custom Search API (free, 100 queries/day — best results)
# Setup: console.cloud.google.com → enable Custom Search API → get key
#        programmablesearchengine.google.com → create engine → copy cx
export GOOGLE_CSE_KEY="AIza..."
export GOOGLE_CSE_CX="12345:abc..."

# NewsAPI fallback (free, 100 req/day)
# Setup: newsapi.org → register → get key
export NEWSAPI_KEY="your_key_here"

# Then run:
python3 main_V5.py
```

If you don't set these, DDG + Google scraping still runs automatically — no setup needed.

## How Each Module Works

### ML Transaction Monitoring (`main_V5.py`)

Trains 3 models on `SAML-D.csv`:
- **Random Forest** (primary — most accurate)
- **Decision Tree** (interpretable)
- **Logistic Regression** (baseline)

Features used: transaction amount, hour of day, cross-border flag, currency mismatch, payment type, whether it's off-hours, day of week.

Risk score 0–100. Thresholds:
- **HIGH**: score > 65
- **MEDIUM**: score 35–65
- **LOW**: score < 35

### Sanctions Screening (`mas_sanctions_scraper.py` + `main_V5.py`)

Scrapes MAS sanctions lists on startup and every 24 hours. Stores in `mas_sanctions.db`.

Matching uses two signals combined:
- **Token Jaccard** (word overlap, weight 0.6)
- **Trigram cosine** (character-level similarity, weight 0.4)

Default match threshold: **0.70** (configurable per request).

### PEP Screening (`kyc_screening_v2.py`)

Scrapes **OpenSanctions** (`opensanctions.org/search/`) — no API key needed. Parses result badges (PEP, Sanctioned, Crime, Terror, etc.) and maps them to risk categories.

Hit threshold: name similarity ≥ 0.30 + at least one risk topic badge.

EDD levels:
- **HIGH** — terrorism or sanctions hit → immediate escalation
- **MEDIUM** — PEP or close associate
- **STANDARD** — no elevated risk

### Adverse Media (`kyc_screening_v2.py`)

Fetch order (all run, results merged and deduped):
1. **Google CSE** — best, needs API key (optional)
2. **DuckDuckGo scrape** — no key, reliable, runs always
3. **Google scrape** — no key, broader, may occasionally hit CAPTCHA
4. **GDELT** — academic news index, no key
5. **NewsAPI** — optional API key fallback

Each article goes through:
1. **Credibility check** — is the source blocked (social media)? whitelisted? or normal scoring?
2. **Keyword scan** — does the title/body contain any risk keywords?
3. **Final score** = `keyword_score × credibility_multiplier`

Articles from whitelisted sources always appear even if keyword score is low.

### Media Whitelist (`media_whitelist.py`)

Four tiers of trusted sources:

| Tier | Score | Examples |
|---|---|---|
| `WIRE_SERVICES` | 0.95 | Reuters, Bloomberg, BBC, FT |
| `FINANCIAL_LEGAL` | 0.88 | OCCRP, ICIJ, Law360, FATF |
| `REGIONAL_PRESS` | 0.82 | Straits Times, CNA, SCMP, Bangkok Post |
| `GOVERNMENT_IGO` | 1.00 | MAS, CPIB, Interpol, OFAC |

**To add a new source:** open `media_whitelist.py`, add the domain (no `www`, no `https`) to the right tier:

```python
REGIONAL_PRESS: frozenset[str] = frozenset({
    "straitstimes.com",
    "mothership.sg",      ← add like this
    ...
})
```

Restart the server after editing. No other files need to change.

## Diagnosing Adverse Media Issues

If adverse media shows 0 articles, hit this in your browser:

```
http://localhost:8000/kyc/media/debug?name=YOUR_TEST_NAME
```

What to look for:

| What you see | Problem |
|---|---|
| `ddg_raw: 0` and `google_scrape_raw: 0` | Network issue or name too obscure |
| `ddg_raw: 5` but `ddg_after_filter: 0` | All sources are being blocked (social/blog domains) |
| `after_filter > 0` but UI shows nothing | Keyword scoring issue — articles found but no keywords matched |
| `google_cse_enabled: false` | No CSE keys set (DDG/Google scrape still runs) |

## Updating Keyword Weights at Runtime

No restart needed. Hit the config endpoint:

```bash
curl -X PUT http://localhost:8000/kyc/media/config \
  -H "Content-Type: application/json" \
  -d '{"weights": {"fraud": 0.85, "corruption": 0.90, "ponzi scheme": 0.80}}'
```

New keywords you add here get merged with the defaults. To reset:

```bash
curl -X POST http://localhost:8000/kyc/media/config/reset
```

## Common Issues

**`ModuleNotFoundError`** — you forgot to activate the venv:
```bash
source venv/bin/activate
```

**Sanctions DB missing** — normal on first run, server builds it automatically. Wait ~30 seconds.

**Models not ready** — first run trains on the CSV, takes a few minutes depending on CSV size. Watch the terminal for `✓ Training complete`.

**Adverse media empty** — run the debug endpoint (see above). DDG and Google scrape should return something for any well-known name.

**Frontend not loading** — make sure `frontend_v0_7.html` is in the same folder as `main_V5.py`. The server looks for it by exact filename.
